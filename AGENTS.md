# AGENTS.md

Guidance for AI agents (and humans) working on this repo. See [README.md](README.md) for what the app does and for the EMUS protocol.

## What this is

iOS app (SwiftUI, iOS 17+, iPhone only) that reads the EMUS G1 BMS of an electric car over Bluetooth LE, tracks consumption per km and sends the state of charge to ABRP. It also runs in the background and has a CarPlay screen. No external dependencies.

## Building

The Xcode project is **not** in git: it is generated by [XcodeGen](https://github.com/yonaskolb/XcodeGen) from `project.yml`.

```sh
xcodegen                     # after every change to project.yml or when files are added/removed
xcodebuild -project EmusLink.xcodeproj -scheme EmusLink \
  -destination 'generic/platform=iOS Simulator' build
```

- Change build settings in `project.yml`, never in `EmusLink.xcodeproj`.
- Without `Config/Local.xcconfig` the project builds for the simulator with the defaults from `Config/Shared.xcconfig`. An iPhone needs your own `DEVELOPMENT_TEAM`.
- `EmusLink/Info.plist` is overwritten by XcodeGen: edit `info.properties` in `project.yml`.
- Raise `MARKETING_VERSION` and `CURRENT_PROJECT_VERSION` in `project.yml` with every change the user installs. Settings → About shows the version, the build time and the bundle ID.
- Keep `APP_BUNDLE_ID` the same between builds: iOS treats another bundle ID as another app, which is installed next to the old one and starts without its data.

## Testing

```sh
xcodegen
xcodebuild test -project EmusLink.xcodeproj -scheme EmusLink \
  -destination 'platform=iOS Simulator,name=iPhone 18 Pro'
```

(Pick a simulator that is installed: `xcrun simctl list devices available`.)

- GitHub Actions runs the same tests on every push to `main` and on pull requests (`.github/workflows/tests.yml`), without `Config/Local.xcconfig` and with the Xcode of the runner, which can be older than yours.
- Unit tests live in `EmusLinkTests/` (XCTest, `@testable import EmusLink`), one file per component.
- Run the tests after every change and add tests for new logic or a fixed bug. Covered: the protocol (CRC, sentences, decoding), `EnergyTracker` (averages, trips, the points of the consumption chart), `SpeedProfile`, `DailyDistance` and `ChargeAdvice`, `BatteryHealth` and `TemperatureMonitor`, `LiveStore` (range), the ABRP telemetry, URL and offline queue, module matching, and the string catalogs.
- Keep logic testable: calculations belong in `EmusProtocol`, `EnergyTracker`, `LiveStore` or a static function, not in a View or a CoreBluetooth delegate. Pass time (`now:`/`at:`) and `UserDefaults` as parameters instead of hard-coding `Date()` and `.standard`; tests use their own `UserDefaults(suiteName:)`.
- The tests run inside the app in the simulator (demo mode). Not tested automatically: Bluetooth, GPS, CarPlay and the layout of the screens. Check those in the simulator or on an iPhone.

## Layout

| File | Role |
| --- | --- |
| `EmusProtocol.swift` | CRC-8, sentence validation, `SentenceAssembler` (BLE packets → lines), `BMSSnapshot` (decoding) |
| `BLEManager.swift` | CoreBluetooth: scanning, connecting, background restoration, polling |
| `EnergyTracker.swift` | Consumption: ∫U·I dt from the BMS, distance from GPS, 100 m segments, trips |
| `SpeedProfile.swift` | Consumption per speed band and the most efficient speed |
| `DailyDistance.swift` | Distance per day, the learned distance per weekday, `ChargeAdvice` |
| `BatteryHealth.swift` | SoH, cell spread and temperatures per day; `TemperatureMonitor` (limits with hysteresis) |
| `AlertNotifier.swift` | Local notifications (temperature warning, also on CarPlay) |
| `ABRPClient.swift` | Telemetry to the ABRP/Iternio API; `TelemetryQueue` keeps what could not be sent |
| `LocationProvider.swift` | GPS |
| `LiveStore.swift` | `ObservableObject` with everything the screens show (main thread only) |
| `AppConfig.swift` | Defaults from the build configuration (xcconfig → Info.plist) |
| `AppModel.swift` | Ties everything together (singleton); demo data in the simulator |
| `DashboardView`, `ConsumptionView`, `InsightsView`, `BatteryHealthView`, `SettingsView`, `Gauges` | SwiftUI screens |
| `CarPlaySceneDelegate.swift` | CarPlay (Driving Task, templates only) |
| `Localizable.xcstrings`, `InfoPlist.xcstrings` | String catalogs: UI texts and permission texts |
| `Tools/testflight.sh` | Archives a release build and uploads it to TestFlight (build number = time of the build). Uploading is the user's call: do not run it without `--archive-only` unless asked |
| `Assets.xcassets`, `Tools/make-icon.swift` | App icon; the PNG is drawn by the script (`swift Tools/make-icon.swift <output.png>`) |

## Conventions

- **Language**: code, comments, documentation and commit messages are in English.
- **Threads**: Bluetooth processing runs on `BLEManager.queue`; `LiveStore` is only updated on the main thread (at most a few times per second). `EnergyTracker`, `SpeedProfile`, `DailyDistance`, `BatteryHealth`, `TemperatureMonitor`, `ABRPClient` and `LocationProvider` are thread-safe with an `NSLock`. Keep it that way.
- **Signs and units**: current from the BMS is positive while charging; power and consumption follow the ABRP convention (positive = consumption, negative = charging/regeneration). Consumption is in Wh/km.
- **Writing to the module**: only to characteristic `BB460003`. `BB460004` is the module's name setting (writing renames the module!) and `0005` is probably configuration too. Do not touch them.
- **Simulator**: no Bluetooth; `AppModel` runs on demo data there, including five weeks of made-up daily distances. Real BLE communication can only be tested on an iPhone near the car.

## Localization

The app is available in English (source language) and Dutch.

- Every user-visible text is English in the code and translated in `EmusLink/Localizable.xcstrings`. The English text is the key.
- In SwiftUI a string literal is localized automatically (`Text("Speed")`, `Button("Save")`, `LabeledContent("Name", …)`). A view that takes a title as a parameter must declare it as `LocalizedStringKey`, not `String`, otherwise it is shown untranslated.
- Outside SwiftUI (log lines, CarPlay, status texts) use `String(localized: "…")`.
- Text that must not be translated (values, units, device names) goes through `Text(verbatim:)` or a `String` variable.
- When you add or change a text, add the Dutch translation to the catalog in the same change. Building in Xcode adds new keys to the catalog automatically; from the command line, add the key by hand. `LocalizationTests` fails on a missing translation, on mismatched placeholders (`%@`, `%lld`) and on stale entries.
- Permission texts (Bluetooth, location) are in `project.yml` (English) and translated in `EmusLink/InfoPlist.xcstrings`.
- Adding a language: add it to every entry in both catalogs, to `CFBundleLocalizations` in `project.yml` and to `languages` in `LocalizationTests`.
- Numbers are formatted with `String(format:)` and are not locale-aware yet (always a decimal point).

## Configuration and secrets

- The repo is public. **Never commit** a Team ID, your own bundle identifier, an ABRP API key, a user token, or the name of someone's module.
- Personal values live in `Config/Local.xcconfig` (git-ignored; example in `Config/Local.xcconfig.example`). `Config/Shared.xcconfig` only holds neutral defaults and includes the local file.
- Adding a setting: default in `Shared.xcconfig`, example in `Local.xcconfig.example`, pass it on through `info.properties` in `project.yml`, read it in `AppConfig.swift`, and describe it in the README. Do not hard-code such values in Swift.
- The ABRP API key and user token are normally entered in the app and stored in `UserDefaults`; the xcconfig values are only an initial value.
- Never add `Config/Local.xcconfig` or `EmusLink.xcodeproj` with `git add -f`.
