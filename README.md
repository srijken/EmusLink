# EmusLink

iOS app that reads the EMUS G1 BMS of an electric Land Rover Defender through the EMUS Smartphone Module (Bluetooth LE) and sends the state of charge to ABRP (A Better Routeplanner), also while in the background.

The app is available in English and Dutch and follows the language of the phone.

## Building

```sh
brew install xcodegen
cp Config/Local.xcconfig.example Config/Local.xcconfig   # and fill in your own values
xcodegen
open EmusLink.xcodeproj
```

Connect an iPhone and press **Run**. The Xcode project is generated by XcodeGen from `project.yml` and is not in git: run `xcodegen` again after changing `project.yml`, anything in `Config/`, or adding files.

## Your own settings

Everything that differs per person or per car lives in `Config/Local.xcconfig`. That file is not committed.

| Setting | Meaning |
| --- | --- |
| `APP_BUNDLE_ID` | Bundle identifier of the app |
| `DEVELOPMENT_TEAM` | Apple Developer Team ID used for signing |
| `DEFAULT_MODULE_NAME` | Name (or part of it) of the EMUS module; empty = search by the EMUS service only |
| `ABRP_API_KEY`, `ABRP_USER_TOKEN` | Optional: pre-filled on a fresh install |

The ABRP credentials and the module name can also be set in the app itself (see below); whatever is saved there takes precedence.

## Testing

```sh
xcodebuild test -project EmusLink.xcodeproj -scheme EmusLink -destination 'platform=iOS Simulator,name=iPhone 18 Pro'
```

The unit tests are in `EmusLinkTests/`. See [AGENTS.md](AGENTS.md) for the code layout and conventions.

## Screens

- **Dashboard**: battery percentage with range, consumption and speed gauges, and tiles for power, average consumption, voltage, temperature and cells.
- **Consumption**: consumption over the last 10, 25 or 50 km as a filled line (regeneration below zero), with the average and the projected range for that distance, plus averages for the trip / 10 km / 100 km and starting a new trip.
- **Insights**: the most efficient speed (consumption per speed band of 10 km/h, with the range of speeds that is within 6 % of the lowest) and learning from trips (distance per day of the week: set, learned and measured, with the charge needed for tomorrow). Both fill up as you drive; the charge figure is advice only, the app does not control charging.
- **Settings**: ABRP, GPS, module, diagnostics and log.

## Languages

English is the source language; Dutch is translated in `EmusLink/Localizable.xcstrings` (a String Catalog, editable in Xcode). The language can also be chosen per app in iOS Settings → EmusLink → Language. To add a language, see the Localization section in [AGENTS.md](AGENTS.md).

## CarPlay

Four tiles (consumption, speed, battery, range); tapping one shows details. It works in the simulator
(*I/O → External Displays → CarPlay*, with demo data). On an iPhone it only works once Apple has approved the
**Driving Task** entitlement for your account (developer.apple.com/contact/carplay); after that, remove
the `[sdk=iphonesimulator*]` restriction in `project.yml`.

## Setting up in the app

- **API key**: request one from Iternio (contact@iternio.com, "Telemetry-only key", free).
- **User token**: ABRP → car settings → Live data → create a token.
- **Module name**: defaults to the value of `DEFAULT_MODULE_NAME`. Part of the name is enough.
- If the car also has an OVMS with the ABRP plugin, switch that off (`script eval abrp.send(0)`) or use a different token, otherwise both send data for the same car.

## Protocol (derived from logs of 22 November 2026)

- Service `BB460001-4A8B-AA9D-E511-9A19C681CA6B`, notify `BB460002`, write `BB460003`.
- Do not write to `BB460004`: it is the module's name setting, so writing renames the module. `BB460005` is probably configuration as well.
- Sentences end in `,XX\r\n`; `XX` = CRC-8/MAXIM (poly 0x31 reflected, init 0) over everything up to and including the last comma.
- Request: `BC1,?,E1` (`VR1,?,D7`, `CV1,?,78`, `BV1,?,4F`, `BT3,?,CB`).
- `BC1`: charge (As), capacity (As), SoC (0.01 %), SoH (0.01 %).
- `CV1`: pack voltage (0.01 V), current (signed, 0.1 A).
- `BV1`: cell count, min/max/avg (2.00 V + n × 0.01 V), pack voltage.
- `BT3`: count, min/max/avg temperature (n − 100 °C).

The EMUS also broadcasts these sentences on its own; about 40 % arrive intact over BLE, the rest fail the CRC and are dropped. That is enough for an SoC update every few seconds, so polling is off by default.
